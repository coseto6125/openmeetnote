# ADR 0002:跨串流去重以 20 ms 量化的音訊區間為鍵

- 狀態:已決定
- 日期:2026-08-01
- 相關:BLUEPRINT.md §5.3.2、§11

## 背景

Provider 重連與串流輪替之後,`provider_stream_id`、`provider_result_id` 與
`rollover_generation` 全都會改變。同一段音訊被重播時,Provider 會給一個全新的
segment id,因此不能用它判斷重複。

藍圖 §11 指定去重鍵是正規化後的 `(track, captured_start_ms, captured_end_ms)`,
並要求「正規化量化單位與容差在 M2 建立 schema 時固定」。

## 決定

量化單位為 **20 ms**,四捨五入到最近的邊界。

判定規則:
- 同區間且正規化文字相同 → 重複,捨棄後者。
- 同區間但文字不同 → 建立新的 revision,不是新片段。

文字正規化只去頭尾空白並壓縮內部連續空白,不動大小寫也不動標點。

## 理由

20 ms 是常見 STT frame 的量級。Provider 對同一段音訊回報的起訖會有數十毫秒抖動,
逐毫秒比對等於永遠判不出重複;量子取得太大則會把相鄰的不同發言誤判成同一段。
以一個 frame 為界,意思是「小於一個 frame 的差異視為同一區間」。

不動大小寫是因為 `API` 與 `api` 在技術會議裡可能是刻意的區別。
不動標點是因為 Provider 修掉標點,正是「同區間但文字不同」該建立新 revision 的情形。

## 後果

- 這個值是 `store::INTERVAL_QUANTUM_MS`,改它會改變既有資料的判重結果,但不會改變已寫入的內容。
- 說話速度極快、句與句間隔小於 20 ms 的情況下可能誤判為同一區間。目前沒有實測資料,
  M1 的雙平台 PoC 產出 drift 與 frame 實測值之後應該回頭檢查這個數字。
